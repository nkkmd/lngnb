# lngnb

**軽量でシンプルな、インターネット上の分散図書館・知識基盤。**

lngnbは、資料を保存し、見つけ、読み、引用し、改訂履歴を辿り、必要な資料を別の場所へ引き継ぐためのシステムです。個人や団体が独立して運営でき、一台でも利用できます。中央アカウントや、他のサーバーへの常時接続は必要としません。

## 現在の状態

開発版は **`0.1.0-dev`** です。工程①〜③と、内部保存基盤・対象回帰の範囲の工程④は完了し、工程⑤「鍵管理とローカル操作の基盤」を継続しています。初期版は未完成で、G1〜G5全体は未合格です。

Linuxでの鍵操作、保存領域の明示初期化・診断、資料の作成・改訂・派生、保存版・分岐・由来の確認、ローカル管理IPC、保存層の根拠復旧確認・明示再開CLIを実装しています。公開HTTP・Web閲覧・検索・リレー間同期などは未実装です。

鍵領域の履歴・整理・再開意思の記録と復旧には内部APIがあります。記録済みguardの明示解除を確認した後も、通常鍵変更への接続は今後の作業です。鍵領域の停止解除・安全な置換・整理のCLI、残存socketの不使用判定・整理は未実装です。

**仕様書・実装計画書の v1.0.0 は文書の版です。** ソフトウェアの開発版は `0.1.0-dev` で、初期版完成やリリースを意味しません。

詳細な到達点と次の作業は[実装計画書の現在地](docs/implementation-plan.md#11-現在地と次の作業)を参照してください。

## 開発用のビルドと確認

確認対象はLinux x86_64（Ubuntu 24.04）です。Rust 1.85.0、Cリンカー、独立照合用のPython 3.12を使用します。取得からビルド・試験までのコマンドは[開発・検証ガイド](docs/development.md#ビルドと通常検証)にまとめています。依存取得後のRust検証はlocked/offlineで行います。

実行時データと秘密情報はリポジトリ外で管理してください。旧保存schemaの自動移行・再初期化は行いません。ビルド成功を正式な保存保証や性能評価の合格とは扱いません。

## 初期版で目指すこと

- 資料の登録・公開、検索・閲覧、固定版の引用、改訂履歴の参照
- 管理者が選んだ資料を、別のリレー（資料を保存・配布するサーバー）から取得し、独立して検証・保持
- バックアップから、資料・不変ID・履歴・信頼設定・公開設定を復元

単一の実行ファイルとローカル保存を基本とし、SQLiteを使用します。外部データベースは必須にしません。閲覧には簡素なWeb画面、資料の作成・署名・管理にはCLIを用いる設計です。

資料の版と本文は不変とし、改訂は新しい版として追加します。発行元の署名、各リレーが採用する信頼起点、公開許可、本文の取得状態は区別します。署名の検証は、資料の内容が真実であることを保証しません。

## 仕様と実装の進め方

規範の判断は[仕様設計書](docs/specification-v1.0.0.md)、実装順序と完了条件の判断は[実装計画書](docs/implementation-plan.md)を基準にします。仕様書の第I部は目的と利用像、第II部は規範、第III部は受入条件、第IV部は形式・API・試験入力です。

初期版の完成は、三つの利用場面と安全性・操作性・軽量性の受入条件を満たしたことを、実装後の試験で確認して判断します。仕様書に記載された計算例の確認を、製品試験の合格として扱いません。

既存のLingonberryやNostrとのプロトコル互換性は要求しない、新規設計です。鍵の交代・復旧や高度な権限管理など、仕様書で後段とした機能は初期必須に含めません。

文書の役割と更新先は[開発・検証ガイド](docs/development.md#文書の更新先)に示します。
